# fusion-ladder — Gemma 4 12B проектирует детали во Fusion 360

Локальная модель `gemma4-12b:q8_0` (Google Gemma 4 12B-it, Q8_0, с Hugging Face) строит и правит
детали во Fusion 360 через встроенный MCP-сервер Fusion. Модель целиком в видеопамяти: 13.4 ГБ,
вместе с Fusion занято 14 из 16 ГБ. Генерация 24 т/с, это потолок карты при 90 Вт.

> **С 31.10.2026** функции CAD и промпт живут в приложении [`fusion-agent/`](fusion-agent/) — терминальном
> чате с моделью для Windows и macOS. Источник правды теперь `fusion-agent/fusion_agent/cad_api.py`
> и `fusion-agent/fusion_agent/prompts/cad12.md`; `cad_api.py` и `prompts/` в корне — история замеров.

## Как пользоваться

`fusion_chat.bat`: консольный чат. Запросы пишутся по-русски («сделай пластину 80 на 50 толщиной 6»,
«скругли углы радиусом 8», «сделай бобышку выше»). Модель работает в новом документе Fusion;
сохранять его или закрыть — решаешь сам. Нужны запущенный Fusion с включённым MCP и Ollama.

`fusion_chat.bat --think` — медленный точный режим для деталей из многих операций: модель
сначала думает. Точнее примерно на треть ошибок, но в 3–4 раза дольше.

## Как устроено

Модель не пишет сырой Fusion API. Перед её скриптом раннер вставляет **функции CAD в миллиметрах**
(`cad_api.py`), и в скрипте остаётся 2–5 строк:

| Что | Функции |
|---|---|
| Готовые тела | `box(..., corner= / base=, corner_radius=)`, `cylinder(..., base=)`, `tube`, `shaft([(d, L), ...], bore=)` — любой вал, штифт, втулка с буртиком; профили `angle_profile`, `channel`, `tee`, `ibeam` |
| Отверстия | `drill(x, y, z, d, axis, depth)` — через точку вдоль оси, сквозное или глухое; `holes(points, d)`; `screw_holes(..., counterbore= / countersink=)` — цековка и зенковка |
| Эскизы | `new_sketch`, `rect`, `circle` (по диаметру), `slot`, `polygon`, `points_on_circle`, `extrude`, `cut`, `revolve` |
| Отделка | `fillet` (скругление), `chamfer` (фаска), `find_edges(parallel_to=, z=, diameter=)`, `shell`, `mirror`, массивы |
| Правки | `set_parameter("d1", 8)` (размеры операций видны в `describe()`), `set_diameter`, `move_circle`, `undo`, `clear` |
| Проверка | `check(size=, diameters=, volume=, operations=)`: модель переписывает числа и слова из запроса, а сравнивает функция |

Раннер (`run_ladder.py`) к каждому запросу прикладывает текущее состояние детали (`describe()`).
Ошибки сокращает до «строка N твоего скрипта: код + суть», а ошибки Fusion функции переводят
в подсказки, что делать. Раннер замечает повторы и обрывает слишком длинные ответы. Если модель
сказала «готово», а деталь не изменилась, её возвращают к работе.

Промпт — `prompts/cad12.md`: справка по функциям, словарик деталей (втулка, швеллер, проточка,
углы пластины...) и примеры. Все примеры проверены во Fusion (`check_examples.py cad12`).

## Наборы задач и проверка

Каждая задача сравнивается с эталоном, собранным во Fusion. Сравниваются объём (допуск 0.5 %),
габариты, диаметры цилиндрических граней, число тел и отсутствие ошибок в истории построения.
Эталоны сверены с ручным расчётом объёмов.

| Файл | Что |
|---|---|
| `cases.json` | уровни 1–4: куб, пластины с отверстиями, втулка, правки, фланец, вал |
| `cases_holdout.json`, `cases_holdout2.json` | новые простые детали; на их ошибках учился промпт |
| `cases_holdout3.json` | **честный набор**: на нём ничего не настраивалось до первого замера |
| `cases_level5.json` | детали из нескольких операций: крышка, опора, кронштейн, шкив, корпус, вилка |
| `cases_photo.json` | деталь по картинке (`photos/`) плюс основные размеры |
| `sessions.json` | сеансы правок по словам в одном разговоре, проверка после каждого шага |

Запуск: `python -I -X utf8 run_ladder.py --cases-file <файл> --all --prompt cad12 --helpers --attach-state --tag <имя>`
(`--think` — режим размышлений), сеансы — `run_session.py --tag <имя>`. Результаты — `results/<имя>/summary.md`.

## Результаты (ночь 30–31.10.2026)

Главное сравнение — одни и те же 12 незнакомых деталей (`cases_holdout3.json`), до и после ночи:

| Версия | Решено | Медиана на деталь | Худший случай |
|---|---|---|---|
| вечер 30.10, в момент ухода владельца (`prompts/cad.md`), 2 прогона | 15/24 (62 %) | 24 с | 263 с |
| v9, 3 прогона | 31/36 (86 %) | 10 с | 184 с |
| итоговая v12, 1 прогон | 11/12 (92 %) | 10 с | 45 с |

100 %, которые были вечером, относились к 11 учебным задачам, на которых настраивался промпт;
на них итоговая версия тоже даёт 11/11. Вечерний прогон сделан с нынешними функциями CAD, где
ночью исправлены ошибки, так что вечерней версии это скорее помогает.

Честные цифры — на наборах, по которым ничего не настраивалось до первого замера:

| Набор | Конфигурация | Решено | Время на задачу |
|---|---|---|---|
| `cases_holdout3.json`, 12 простых деталей × 3 прогона | v9, быстрый режим | **31/36 (86 %)** | медиана 10 с, 2/3 задач до 15 с |
| `cases_level5b.json`, 6 деталей из нескольких операций × 2 | v11, быстрый режим | **9/12 (75 %)** | медиана 41 с |
| то же | v11, с размышлениями, лимит ответа 1200 токенов | 11/12 (92 %) | медиана 138 с |
| то же | v11, с размышлениями, лимит 4000 (так работает `--think`) | **6/6** | медиана 94 с |

Итоговая версия v12 (быстрый режим, утро 31.10): уровни 1–4 и два набора простых деталей —
35/35 (медиана 9 с, 90 % задач до 23 с); новый уровень 5 — 6/6; по картинке — 5/5; сеансы — 14/14;
третий набор — 11/12 (медиана 10 с, максимум 45 с; к этому моменту в промпт уже вошло одно правило
из разбора его ошибок, поэтому честная цифра для него — 86 % выше).

На наборах, на которых учился промпт: уровни 1–4 и два набора простых деталей — 34/35 (v11).
Сеансы правок по словам (8 правок пластины, 6 правок вала в одном разговоре) — 14/14 шагов
в каждом прогоне v8, v10, v10, v11, обычно 4–6 с на правку. Детали по картинке — 5/5 (v10).

Для сравнения: без функций CAD, на сыром API Fusion, модель решала 2 из 3 задач уровня 1
за 83–263 с (медиана 88 с).

Слабое место — раскладка в пространстве на деталях из нескольких операций: с какой стороны
«торец с пазом», на какой полке отверстие, ширина или глубина канавки. Режим размышлений
это заметно лечит, но медленнее: медиана 1.5–3 минуты на деталь, отдельные детали до 20 минут.
Размышлениям нужен запас токенов: с лимитом 1200 обрезалась половина ответов.

## Что выяснилось

- **Инструменты работают, правила — нет.** Швеллер, проточку и «углы пластины» модель путала,
  сколько их ни объясняй словами. Всё вылечилось готовыми функциями (`channel`, `shaft`,
  `corner_radius`), в которые нужно только подставить числа из запроса.
- **Числа сравнивает функция, а не модель.** Если в `describe()` нет нужного диаметра, модель
  этого не видит. Если сама переписывает числа в `check()`, ошибку ловит функция. Слабое место:
  модель иногда «чинит» `check`, вписывая туда измеренное значение. Правило это запрещает,
  но соблюдается оно не всегда.
- **Модель копирует ближайший пример.** Пока все примеры начинались с прямоугольника, диск
  выходил квадратным. Из-за `find_circles(...)[0]` в примере правилось одно отверстие из четырёх.
- **Значения по умолчанию опасны.** `cylinder(...)` без координат вставал в начало координат,
  а не на отверстие. Теперь место указывается явно (`base=` / `corner=`).
- **Время уходит на рассуждения в комментариях.** Без режима размышлений модель думает прямо
  в коде: до 4700 токенов, 200 с. Против этого — лимит длины ответа и функции, где думать не о чем.
- **Особенности Fusion:** сквозной вырез `setAllExtent(Symmetric)` режет только в одну сторону;
  сквозной вырез туда, где нет тела, падает; упавший скрипт Fusion откатывает целиком;
  встроенный MCP после сотен запусков теряет вывод `print` (обход — `OUTPUT_GUARD` в `mcp_client.py`).
